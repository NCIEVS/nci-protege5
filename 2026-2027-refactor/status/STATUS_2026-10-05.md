# NCI Protégé Refactor — Status (2026-10-05)

**Goal:** Make the Virtuoso triplestore the lazy, authoritative source of truth
for the Thesaurus, with the OWL API retained only for file input/output. This
removes the long-standing requirement to hold the entire ontology in memory.

## Plan-level status

| Step | Description | Status |
|------|-------------|--------|
| 0–2 | Foundations: branches, OWL↔RDF I/O seam, Virtuoso write-path with revision tracking, per-class commit gate | **Done** |
| 3 | Migrate the demanding consumers (navigation tree, search, classifier, edit path) onto the lazy/Virtuoso model | **Complete, hardened, and performance-tuned at full scale** |
| 4 | Remove the OWL API as the in-memory runtime model and retire the now-dead modules | **Not started** |

The period since the last status (2026-09-23) was spent closing the remaining
correctness gaps in the lazy edit path and making server-side classification fast
enough for routine curation. No change to the four key architecture decisions.

## Progress since 2026-09-23

### Classifier performance (headline)

Full-Thesaurus classification dropped from **~7.4 minutes to ~1.7 minutes (4.3×)**,
with **bit-for-bit identical output** (242,596 inferred axioms, spot-checked in the
inferred-results view). The work was driven by phase-level timing added to the
server classify path:

- **Reasoning algorithm 365s → 63s (5.8×).** Two changes, both output-preserving:
  memoize the top/bottom (LUB/GLB) searches so the multiple-inheritance graph is no
  longer re-walked once per path; and, using the structural subsumption invariant
  (A subsumes B ⇒ A's primitives ⊆ B's primitives), skip the bottom search for a
  primitive class when it is provably empty. A tracked per-class subsumee count
  makes the skip safe (it only skips when no classified class can be subsumed).
- **Inferred-graph write 60.5s → 19s (3.2×).** Replaced the ~485 small SPARQL
  `INSERT DATA` round-trips with a single atomic bulk graph replace against
  Virtuoso's CRUD endpoint.
- The remaining time is the binary-OWL head load (~22s, unchanged — a fast format
  and a small slice) plus axiom-to-RDF rendering on the write side.

### Lazy edit-path hardening

- **Merge and retire** now retarget references across the whole ontology via
  Virtuoso, rather than only the sparse in-memory signature; re-parenting under the
  retire/merge roots and the history (old-parent) annotations are correct.
- **Name/existence resolution** — duplicate-name detection and IRI/name lookups
  resolve against the store, so they are complete even for classes that have never
  been browsed in the session.
- **Filler selection** in the restriction editor browses the class hierarchy
  directly from Virtuoso.
- **Entity finder / autocomplete** resolves class names against the store, so a
  typed or pasted name finds any class, not just materialized ones.
- **Navigation rendering** — classes render in bold (the "has statements" cue)
  under the lazy model.
- **Classification UI** — running a classify now shows a progress dialog.

### Search — clarified and operational

Confirmed the embedded Lucene search dialog and the search tab share a single,
server-seeded index. Incomplete results seen under lazy mode were traced to a
stale/absent **server-side** index (not a client defect); a server reindex restored
full coverage. No code change to the search buttons was needed.

## Remaining work

- **Step 4 (the main outstanding effort):** retiring the OWL API as the in-memory
  runtime model. The lazy read/write path still assembles OWL-API objects
  internally, and the editing, rendering, and commit layers still speak those
  types. Completing this requires the next version of the internal I/O layer. The
  OWL API file parsers are kept by design.
- **Optional classifier follow-ups:** the write-side axiom rendering (~18s) is a
  smaller lever if needed; incremental (re)classification remains the hard problem,
  owing to the cascade/blast-radius of re-placing a moved class.
- **Minor application-level and robustness items** identified during testing; none
  block the core workflows.

## Summary

Since 2026-09-23, Step 3 moved from "working end-to-end" to "hardened and
performance-tuned at full scale." The headline is classification: a 4.3× speedup
with identical results, making server-side classify practical for routine use. The
lazy edit path's remaining correctness gaps — merge/retire retargeting, name
resolution, and filler selection — are closed. Step 4, removing the in-memory
OWL-API runtime model, remains the next strategic milestone.
