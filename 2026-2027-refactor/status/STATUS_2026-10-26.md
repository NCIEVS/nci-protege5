# NCI Protégé Refactor — Status (2026-10-26)

**Goal:** Make the Virtuoso triplestore the lazy, authoritative source of truth
for the Thesaurus, with the OWL API retained only for file input/output. This
removes the long-standing requirement to hold the entire ontology in memory.

## Plan-level status

| Step | Description | Status |
|------|-------------|--------|
| 0–2 | Foundations: branches, OWL↔RDF I/O seam, Virtuoso write-path with revision tracking, per-class commit gate | **Done** |
| 3 | Migrate the demanding consumers (navigation tree, search, classifier, edit path) onto the lazy/Virtuoso model | **Complete; running on the NCI server and now validated end-to-end against a large ontology** |
| 4 | Remove the OWL API as the in-memory runtime model and retire the now-dead modules | **Direction decided; targeted increments delivered; full model replacement deferred by choice** |

The period since the last status (2026-10-13) had three threads: simplifying the
client–server synchronization model so conflicts are handled accurately and with
less friction; consolidating the two NCI-maintained plugins into the main build
to remove a version-mismatch risk and simplify release packaging; and a first
end-to-end run against a large ontology. The four key architecture decisions are
unchanged.

## Progress since 2026-10-13

### Large-ontology end-to-end validation (headline)

The refactored system was exercised against a large ontology on the real editing
workflow, not a toy example. In this run the ontology loaded, the Virtuoso triple
store and the search indices were built, and classification completed — all
successfully. Testing is ongoing, but this is the first time the full pipeline
(load → index → classify → edit) has been driven through at realistic scale on
the new architecture, and the early results are clean.

### Simpler, safer client–server synchronization

The old design asked editors to watch an "updates available" button and click to
refresh, and in some situations one editor's changes could be quietly merged on
top of another's. That was reworked:

- **Conflicts are now caught at the moment an editor saves**, and are reported
  for the exact class in conflict with a clear "please update" message — instead
  of being silently merged. Two editors working on genuinely different classes
  still save without any friction.
- **Idle clients refresh themselves in the background**, so an editor who steps
  away comes back current without doing anything.
- **An editor in the middle of a change is never interrupted** or forced to
  refresh; the one moment that matters — saving — is where conflicts surface.

The net effect is that the lazy model's conflict handling is both more accurate
(no silent overwrites) and much less intrusive day-to-day.

### Consolidated plugin packaging; removed a version-mismatch risk

The classifier and the Lucene search/index component are NCI-maintained plugins.
Previously they were separate projects: clients received them through Protégé's
plugin auto-updater, while the server got them through a separate manual step.
That created a real risk — a client could auto-update one of them ahead of the
server, breaking the shared data/index contract between the two.

- Both are now **built as part of the main Protégé build at a single, matched
  version** and packaged into both the client and the server. The independent
  auto-update path for them is retired, so client and server always run the
  identical plugin code from the same release.
- The **server packaging was simplified** — a fragile hand-rolled step that
  unpacked bundled libraries was replaced with standard dependency resolution.
- Hardening this clean-release path surfaced a chain of packaging defects that
  would have caused the classifier, the search indexer, and the Lucene search
  tab to **silently fail to load** on a from-scratch release build. Each was
  root-caused and fixed, and a safeguard was added so the underlying cause
  (critical plugin files being omitted from the packaged release) cannot recur.

## Remaining work

- **Step 4 full model replacement** — still deferred by decision, to be
  revisited once remote/VPN deployment is fully bedded in. The rendering
  increments that were previously queued were found already in place, so no open
  Step-4 code work remains beyond the deferred full replacement.
- **Deferred robustness items, unchanged:** making the server's pause state
  survive a restart (a manager can re-login to re-pause in the meantime); a
  cosmetic refresh notice on the Active Ontology tab that clears itself; and the
  pause-permission model (whether other managers may lift a pause), still under
  consideration.
- **Rollout and continued validation:** distribute the newly consolidated
  client/server build to editors and continue exercising the large baseline over
  the VPN.
- The OWL API file parsers are kept by design throughout.

## Summary

Since 2026-10-13 the headline is the first clean **end-to-end run against a large
ontology** — load, triple-store and search-index build, and classification all
completed on the new architecture, with testing continuing. In parallel we made
the day-to-day editing experience both safer and simpler: conflicts between
editors are now caught precisely at save time and scoped to the class in
question, rather than prompting constant manual refreshes or risking silent
overwrites. We also consolidated the two NCI-maintained plugins (the classifier
and the Lucene search component) into the single main build so the client and
server always run identical versions — closing a real version-mismatch risk —
and in doing so found and fixed a set of packaging defects that would otherwise
have let core features fail silently on a clean release, with a safeguard added
to prevent recurrence. The project remains on plan, with Step 4's full scope
consciously deferred rather than rushed.
