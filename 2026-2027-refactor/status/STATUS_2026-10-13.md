# NCI Protégé Refactor — Status (2026-10-13)

**Goal:** Make the Virtuoso triplestore the lazy, authoritative source of truth
for the Thesaurus, with the OWL API retained only for file input/output. This
removes the long-standing requirement to hold the entire ontology in memory.

## Plan-level status

| Step | Description | Status |
|------|-------------|--------|
| 0–2 | Foundations: branches, OWL↔RDF I/O seam, Virtuoso write-path with revision tracking, per-class commit gate | **Done** |
| 3 | Migrate the demanding consumers (navigation tree, search, classifier, edit path) onto the lazy/Virtuoso model | **Complete, and now running on the NCI server** |
| 4 | Remove the OWL API as the in-memory runtime model and retire the now-dead modules | **Direction decided; first low-risk increment delivered; full model replacement deferred by choice** |

The period since the last status (2026-10-05) had three threads: standing the
system up on the actual NCI server, making the strategic call on Step 4, and
closing a set of real bugs found by exercising the monthly baseline (publish)
workflow end-to-end. The four key architecture decisions are unchanged.

## Progress since 2026-10-05

### Running on the NCI server (headline)

The refactored system now runs on the actual NCI remote server, not just a
developer workstation. The target environment is stricter than the dev box, which
surfaced several deployment-only issues — all found and fixed:

- **Project open was blocked** by the remote Virtuoso's query-cost limit (a safety
  setting the dev box leaves off). Root-caused to one specific query pattern in the
  navigation warm-up and corrected; project open now completes in a few seconds.
- **Plugin packaging** was corrected so the server's classpath carries the
  classifier and search dependencies it needs when run from the packaged build.
- **The classifier crashed the remote database** on write: a single very large
  write overwhelmed the remote Virtuoso. The write is now batched, matching the
  proven bulk-load path; full-Thesaurus classify completes on the server.
- **Project deletion** now clears large graphs in bounded batches instead of
  exceeding the database's time limit and leaving a partially-deleted graph.

### Step 4 — decision and first increment

We made an explicit cost/benefit decision on Step 4 (documented for the record):

- **The original driver for Step 4 was memory/scale, and the lazy model already
  solved that.** Fully removing the OWL API runtime model is now mostly internal
  dependency cleanup — high effort, high risk to the editing path, and no new
  user-visible benefit. It is therefore **deferred, not cancelled**.
- Instead we are taking a **targeted, low-risk path** governed by a **two-mode**
  design: opening a local file behaves like classic Protégé (everything works),
  while opening a server project uses the NCI editing surface and makes the other
  standard tabs browse-only. A full audit of the standard tabs backed this.
- **Delivered this period:** (1) a guard that disables generic create/delete on the
  standard tabs when a server project is open — which removes a latent
  data-integrity risk (a stock delete could otherwise orphan references); and
  (2) the **Active Ontology metrics** (class/property/individual counts) are now
  served accurately from Virtuoso instead of showing a fraction of the real totals.

### Monthly baseline (publish) workflow fixes

Running the manager's monthly baseline process — pause the server, review, adjust
the version/date, squash history, re-open — against the new architecture surfaced
and fixed several real issues:

- **Ontology version/date annotations** (which the manager edits as part of
  publishing) were not being written to Virtuoso and so were invisible to the
  lazy client, which led to duplicates. They are now persisted on both the load and
  commit paths and shown correctly, so edits replace rather than duplicate.
- **Server maintenance (pause) mode** was locking out the very manager who paused
  it, preventing the required mid-process re-open. The manager who holds the pause
  now retains full access while everyone else stays frozen.
- A **delete-after-retire** control that was inert under the lazy model (a built-in
  property it depended on wasn't visible in the sparse view) was fixed.

## Remaining work

- **Step 4 full model replacement** — deferred by decision; to be revisited once
  the remote/VPN deployment is fully bedded in. The remaining Step-4 increments
  (two internal rendering hot-spots) are low-risk and queued.
- **Two robustness items, deferred intentionally:** making the pause state survive a
  server restart (the manager can simply re-login to re-pause in the meantime), and
  a cosmetic refresh warning on the Active Ontology tab that clears itself. The
  pause-permission model (whether other managers may also lift a pause) is under
  consideration.
- The OWL API file parsers are kept by design throughout.

## Summary

Since 2026-10-05 the headline is that the refactored system is **running on the
real NCI server**, with the deployment-specific issues (a query-cost rejection,
plugin packaging, a classifier write that crashed the remote database, and
large-graph deletion) found and fixed. In parallel we made the strategic call on
Step 4: because the lazy model already solved the memory/scale problem, the
expensive and risky full removal of the OWL API runtime model is **deferred** in
favor of a targeted, lower-risk path that keeps the standard Protégé tabs safe and
accurate — the first pieces of which are delivered. Finally, exercising the
manager's monthly publish (baseline) workflow end-to-end surfaced and closed
several genuine bugs, so that curator-critical process now works under the new
architecture. The project remains on plan, with Step 4's full scope consciously
deferred rather than rushed.
